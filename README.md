# Telegram-бот осмотров авто

MVP-бот для проведения осмотров автомобиля сотрудником в личном чате Telegram и публикации итога в чат ФП от имени бота.

## Возможности

- сценарии: `Сдача`, `Пересадка`, `Выдача авто`, `Плановый осмотр`, `Осмотр после ДТП`;
- `Пересадка` публикуется как `сдал` и требует те же фото, что и `Сдача`;
- обязательные фото госномера, а для сдачи/пересадки ещё фото приборной панели;
- повреждения требуют фото и текстовое описание;
- оценки 1-5 для сдачи, пересадки и планового осмотра;
- комментарий обязателен при оценке ниже 4;
- сохранение черновиков и завершённых осмотров в SQLite;
- справочник парковых номеров из Excel как подсказка, без запрета новых номеров;
- публикация фото и итогового сообщения в ФП через `send_photo`/`send_media_group`/`send_message`;
- экспорт оценок и истории авто в Excel для руководителя.

## Команды

- `/start`, `/help` — стартовое меню;
- `/new_inspection` — новый осмотр;
- `/cancel` — отменить текущий осмотр;
- `/my_drafts` — показать черновики;
- `/tire_check` — включить разовую проверку резины, только для `SUPERVISOR_USERNAME`;
- `/tire_check_status` — статус активной проверки резины;
- `/active_campaigns` — активные управленческие кампании;
- `/stats_today` — управленческая сводка за сегодня;
- `/tire_check_stop` — остановить активную проверку резины, только для руководителя;
- `/export_scores` — Excel с оценками за период, только для `SUPERVISOR_USERNAME`;
- `/export_problems` — Excel с проблемными авто за период, только для руководителя;
- `/history_auto {plate}` — история по авто, только для руководителя.

## Запуск локально

```bash
cp .env.example .env
python3.11 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m app.main
```

## Docker / BotHost

```bash
docker build -t inspection-bot .
docker run --env-file .env -v "$(pwd)/data:/app/data" inspection-bot
```

Для BotHost/GitHub deployment задайте переменные окружения:

```env
BOT_TOKEN=
FP_CHAT_ID=-1001905865504
DATABASE_URL=sqlite+aiosqlite:////app/data/bot.db
SUPERVISOR_USERNAME=Fedos_AV
SUPERVISOR_TELEGRAM_ID=
INSPECTION_STAFF_USERNAMES=
DATA_DIR=/app/data
VEHICLE_PLATES_XLSX=/app/seed/park_cars.xlsx
PLATE_AUDIT_ENABLED=true
PLATE_AUDIT_HOUR=4
SERVICE_USERNAME=Norblacksmith
SERVICE_AMOUNT_REMINDER_INTERVAL_MINUTES=10
REMINDER_FIRST_DELAY_MINUTES=10
REMINDER_INTERVAL_MINUTES=30
MAX_REMINDERS=3
FP_MANAGER_RESPONSE_DELAY_MINUTES=45
OFFICE_TIMEZONE=Europe/Moscow
MANAGER_DAYS_OFF=pagorodu:thu,fri;Wuggfi:wed,thu;lalalas19:sat,sun;serb_98:sat,sun
```

Важно: бот должен быть добавлен в чат `ФП - фотофиксация повреждений` и иметь право отправлять сообщения/медиа.
Для ссылки `https://web.telegram.org/a/#-1001905865504` значение переменной `FP_CHAT_ID` должно быть `-1001905865504`.

`VEHICLE_PLATES_XLSX` уже указывает на встроенный файл `seed/park_cars.xlsx` с колонками
`Марка`, `Модель`, `Номер`, `Статус`. Файл используется только как подсказка для
распознавания/проверки: если сотрудник вводит новый номер, которого нет в таблице,
бот всё равно принимает и сохраняет его.

## Контроль закрытия повреждений

Если сотрудник завершил осмотр с повреждениями, бот после публикации отчёта в ФП сам запускает контроль:

- пишет `@Norblacksmith` короткий запрос оценки/суммы reply к опубликованному отчёту;
- пишет менеджерам, которые сейчас на смене, и показывает кнопки `💰 Оплата / списание` и `☑️ Без списания`;
- для ДТП, где водитель не виноват, показывает только `🔎 Проверено без списания`;
- не дублирует фото и полное описание повреждений в служебных сообщениях;
- повторяет напоминания по расписанию и эскалирует после `MAX_REMINDERS`;
- закрывающее сообщение отправляет reply к исходному отчёту осмотра.

Для `Сдача` и `Пересадка` первое повторное напоминание идёт через `REMINDER_FIRST_DELAY_MINUTES`.
Для `Плановый осмотр` и `Осмотр после ДТП` — через `FP_MANAGER_RESPONSE_DELAY_MINUTES`.
Если срок попадает за пределы рабочего дня `09:30-18:30`, напоминание переносится на следующий рабочий день в `09:45` с учётом `MANAGER_DAYS_OFF`.

## Ежедневная сверка номеров

Если `PLATE_AUDIT_ENABLED=true`, бот раз в сутки в `PLATE_AUDIT_HOUR` по Москве
сверяет фото госномера за предыдущий день с номером, который выбрал или ввёл сотрудник.
Отчёт отправляется руководителю `Fedos_AV` в личные сообщения и содержит ссылки на сообщения
осмотров в ФП. Для гарантированной доставки укажите `SUPERVISOR_TELEGRAM_ID`; если он пустой,
бот попробует найти id руководителя по действиям в базе.

## Разовая проверка резины

Команда `/tire_check` доступна только руководителю `Fedos_AV`.
Руководитель выбирает режим:

- `По всем проходящим авто` — бот добавит шаг резины во все обычные осмотры, пока кампания активна;
- `Загрузить Excel со списком` — бот ждёт `.xlsx` с колонкой `Номер` и добавляет шаг резины только этим авто.

В шаге резины сотрудник выбирает `Зимняя` или `Летняя`, затем ставит оценку 1-5.
Бот обязательно просит фото резины/протектора. Если оценка ниже 4, комментарий обязателен.
Поля резины выгружаются в руководительский отчёт `/export_scores` и историю авто.

Активная проверка резины по умолчанию действует до конца дня. Для списка авто бот отмечает машины
как проверенные и автоматически закрывает кампанию, когда все номера из списка прошли осмотр.
Статус и прогресс доступны через `/tire_check_status`.

## Навигация сотрудника

После `/start` бот закрепляет кнопки:

- `Сбросить осмотр` — сначала спрашивает подтверждение, чтобы не отменить осмотр случайно;
- `Назад` — возвращает на предыдущий шаг;
- `Вперёд` — возвращает на шаг, с которого сотрудник случайно ушёл назад.

`/my_drafts` показывает незавершённые осмотры с кнопками `Продолжить` и `Отменить`.

## OCR госномера

OCR работает как опциональный best-effort режим. Если на сервере установлен `pytesseract` и системный
Tesseract OCR, бот попробует распознать номер по фото и покажет кнопки `Да, верно` / `Исправить номер`.
Если OCR недоступен или ничего не распознал, бот сразу просит ввести номер вручную.

## Фото

В MVP фото хранятся у Telegram. В SQLite сохраняются `telegram_file_id` и `telegram_file_unique_id`,
по которым бот может повторно отправлять эти фото в ФП. OCR-временные файлы госномера сохраняются в
`DATA_DIR/ocr`. Если нужно независимое архивное хранение всех фото, следующий шаг — включить скачивание
оригиналов в `DATA_DIR/photos` и добавить пути файлов в таблицу `inspection_photos`.

## Проблемные авто

Команда `/export_problems` выгружает авто за период, где есть хотя бы один признак:

- есть повреждения;
- любая оценка кузова, техники, оклейки или резины ниже 4.
